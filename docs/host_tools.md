# Host tools

Everything runs from the repository root:
- **Python:** a virtual environment in `.venv_local`, created with `python3 -m venv .venv_local && .venv_local/bin/pip install -r requirements.txt`. `pip install -e .` also installs the commands `esp32-capture`, `esp32-ssb-live`, `esp32-ssb-monitor`, `esp32-cell-scan`, `esp32-band-survey` and `esp32-sigmf-export` (the `python -m capture.<tool>` forms below work either way).
- **MATLAB:** add `matlab/` (and `tests/` for the tests) to the path.

| Module | Purpose |
|---|---|
| `capture/esp_sdr.py` | serial client for ESP-SDR/ESPsoup: SYNC, INFO/CAPS/LIMITS, FREQ, GAIN, DCCAL, CAP/CAPT bursts, `ssb_stream()` for SSBDET, RTS reset |
| `capture/capture_bursts.py` | command line: `info`, `gain-scan`, `capture`, `ssb-stream` |
| `capture/session.py` | session format, reader, `SsbRecorder` |
| `capture/nr_ssb.py` | the NR SSB receiver in NumPy |
| `capture/nr_pbch_tables.py` | polar tables of the PBCH, generated by `matlab/export_pbch_tables.m` |
| `capture/ssb_live.py` | live view (board or replay): the window, its state and event handling, `main` |
| `capture/ssb_live_panels.py`, `ssb_live_channel.py`, `ssb_live_plots.py` | parts of the live view's window: Cells and MIB tabs, Channel tab, the figure |
| `capture/ssb_sources.py` | no GUI: the board (SSBDET, reconnects), scans and replays as event sources, the decoder worker, channel helpers; shared by the live view, the monitor and the cell scanner |
| `capture/ssb_monitor.py` | headless monitor: JSON/CSV/UDP output, alerts |
| `capture/cell_scan.py` | cell scanner: the whole SSB raster around one or more LOs |
| `capture/sigmf_export.py` | sessions as SigMF recordings with SSB annotations |
| `capture/band_survey.py` | stitched spectrum of band surveys, occupied stretches |
| `capture/session_spectrum.py` | averaged spectrum of sessions with SSB markers |
| `matlab/ssb_detect.m`, `detect_session.m` | reference detector for one burst / a whole session |

## Captures

```bash
.venv_local/bin/python -m capture.capture_bursts info --port /dev/ttyACM0
.venv_local/bin/python -m capture.capture_bursts gain-scan --port /dev/ttyACM0 --freq 2131 --rate 20 --bits 8
.venv_local/bin/python -m capture.capture_bursts capture --port /dev/ttyACM0 --freq 2131 --rate 20 --bits 10 \
    --gain auto --count 300 --label n1_2131 --note "board antenna, indoors"
.venv_local/bin/python -m capture.capture_bursts ssb-stream --port /dev/ttyACM0 --freq 2131 --ssb 2125.45 \
    --nid2 0 --cfo 12000 --duration 30                                     # on-chip SSB detection
```

**Options:**
- **`--freq`** is the LO in whole MHz. Several values capture round robin, `--per-freq` bursts each, which makes a band survey.
- **`--gain auto`** scans the gain indices and takes the highest without clipping; give a number to fix it.
- **`--rate`** is in MS/s (80, 40, 20, 10, 8, 4).
- **`--bits`** is 8 (CAP16) or 10 (CAP20).
- **`--count` / `--duration`** say when to stop.
- **`--label` and `--note`** go into the session.

### Session format

A session is a folder `data/<YYYYmmdd_HHMMSS>_<label>/`:
- **`session.json`:** the device's answers (INFO, CAPS, LIMITS, VERSION, FWOPT) and the settings.
- **`bursts.bin`:** all payloads as received, appended.
- **`bursts.jsonl`:** one line per burst: byte offset and length, format, `n`, `fs`, `freq_mhz`, gain, `t0_us` (time of the first sample, µs since boot), CRC result, temperature, and for SSBDET cuts the `ssb_*` fields (`ssb_pss_in_cut`, `ssb_cfo_hz`, `ssb_nid2`, `ssb_stat`, `ssb_mode`).
- **`ssb_events.jsonl`** (SSBDET only): every frame, also the header-only ones, with `t_pss_us`.

**Readers:**
- Python: `capture.session.load_session(folder)` → `(meta, records, iq_list)`.
- MATLAB: `esp_load_session(folder, 'FreqMHz', ..., 'Index', ..., 'MetaOnly', ...)`.

Both negate Q as the firmware sends −Q.

## Cell scanner

```bash
.venv_local/bin/python -m capture.cell_scan --port /dev/ttyACM0 --freq 2131 2670             # two LOs
.venv_local/bin/python -m capture.cell_scan --port /dev/ttyACM0 --freq 2g 5g                 # the C5's whole range, 152 LOs
.venv_local/bin/python -m capture.cell_scan --port /dev/ttyACM0 --freq 2580-2610 --scs 30    # only 30 kHz SSBs
.venv_local/bin/python -m capture.cell_scan --session data/<plain burst session> --ppm -3.1     # offline
```

`--freq` takes LOs in whole MHz, ranges (`2175-2715/12`, step 12 MHz if omitted) and `2g` / `5g`: the C5's whole 2130–2730 and 4790–5990 MHz in 12 MHz steps. Each LO covers SSB centres within ±6.1 MHz, so 12 MHz steps leave no gap.

**What it does at each LO** (`cell_scan.sweep`):
1. **Gain:** auto (the highest gain index without clipping) or `--gain`.
2. **Bursts, timed on the board's clock** (`capture_lo`):
   - An SSB of a 20 ms-periodic cell can start anywhere in the period. A burst (1.64 ms) holds it whole only if it starts in a 1.3 ms window.
   - So the scanner keeps a map of the start times each burst covered, delays every further burst (0–20 ms) to land on the longest stretch still missing, and stops when every start time was covered `--looks` times (default 2, at most `--bursts`, default 100).
   - On the board (24 Nov), 2 looks took 47 bursts per LO in the median (41–65), about 5.5 s with the gain scan. A simulation with the burst spacings of the 23/24 Nov surveys (94 ms, mostly within ±1 ms) gave 58, and 89 for untimed bursts.
   - The old fixed 60 untimed bursts covered only 85–97 % of the period at some LOs of the 24 Nov survey, so a cell with a single beam could be missed.
3. **The search:** every GSCN position within ±6.1 MHz, all N_ID2, in 5 kHz CFO steps (10 kHz for 30 kHz SSBs), with `nr_ssb.pss_search_raster`; then SSS, PBCH and MIB.
4. **SSB numerologies per LO** (`ssb_cases`):
   - 15 kHz case A (L_max 4) below 3 GHz;
   - 30 kHz case C (L_max 8) as well where a TDD band lies within the LO's span (n40 2300–2400, n53/n41/n38 2483.5–2690 MHz);
   - only 30 kHz case C at 5 GHz (n46, n79).
   - `--scs 15|30` forces one for every LO.
5. **CFO window** (`cfo_window`):
   - Without `--ppm`: around 0, ±12 ppm (at least `--cfo-span`, 30 kHz), because the crystal has been seen anywhere from −7.3 to +2.9 ppm.
   - The first decoded cell measures the crystal; after that, each LO searches ±2 ppm around it (3 CFO steps instead of 13). `--cfo` fixes the window for all LOs.
6. **Overlap:** the PC searches one LO's bursts while the board captures the next.

**Time:**
- **Measured on the board** (24 Nov, 2 looks, auto gain, 2 decoder processes): `2g 5g` took 14.1 min, of which the 2 GHz part took 6.0 min.
- **Estimate for `5g` alone:** about 9 min (`sweep_eta_s`, fitted to that run).
- **Bottleneck:** the 2 GHz part is limited by the PC search (15 and 30 kHz in the TDD bands), the 5 GHz part by the capture.

**Limit:** 2 looks give every SSB about two chances. A weak cell next to a strong one can be missed. On 24 Nov this happened to PCI 166 (−4.4 dB), the sector next to PCI 165, which 100 untimed bursts had found. Tracking PCI 165 shows PCI 166 as well (the PC tries the other N_ID2 on every cut), or use 3–4 looks.

**PC load:** with the crystal known, one burst takes 127 ms of one core at 2 GHz, plus 273 ms for 30 kHz in the TDD bands, and 80 ms at 5 GHz. Two decoder processes keep up with the board.

**What it prints:** a table of cells: SSB frequency, GSCN, PCI, SSBs, MIBs, SNR, RSRP, CFO, SSB indices and the main MIB fields. It writes the table as JSON (`results/cells_<time>.json`); `--record` keeps the bursts.

**Example:** on the 23 Nov captures it finds PCI 165 at GSCN 5314 (n1) and PCI 317 at GSCN 6669 (n7, MIB: k_SSB 6, pdcch-ConfigSIB1 16).

## Live view

```bash
.venv_local/bin/python -m capture.ssb_live --port /dev/ttyACM0 --freq 2131                        # finds the cell itself
.venv_local/bin/python -m capture.ssb_live --port /dev/ttyACM0 --freq 2670 --ssb 2667.75 --nid2 2 --cfo 8000 --record
.venv_local/bin/python -m capture.ssb_live --replay samples/ssbdet_pci165_150cuts [--speed 0]
.venv_local/bin/python -m capture.ssb_live --replay data/<plain burst session> --ssb 2125.45    # PSS search on the PC
```

**Live mode:**
1. Auto gain (or `--gain`).
2. Without `--ssb` (or `--ssb auto`): the cell scanner around the LO picks the cell with the most MIBs.
3. Without `--nid2`/`--cfo`:
   - firmware version 3 searches on the chip (all N_ID2, `--cfo-span` 30 kHz);
   - older firmware: a PC scan at the SSB frequency.
4. SSBDET with that cell. With version 3, cuts are decimated to 5 MS/s by default (`--raw-cuts` for raw); every frame then also carries the chip's PCI.

Every cut is decoded in a separate process. It is also tried with the other two N_ID2 at the same PSS position, so co-sited sectors show up. Such a cell is kept only with a decoded MIB, or with an SSS statistic of at least 18. `--record` stores the session like `ssb-stream`.

**Recovery:**
- If the board drops off USB or stops answering, the view reopens the port (by its Espressif ID if the name changed), resets the board through RTS if needed, and restarts SSBDET with the last CFO.
- If no line comes for 15 s, it sends STOP. An END reply means the board is alive but sees no SSB; after two such runs it scans again.
- The board's clock restarts at 0 on a reset: the time axis is continued, and the timing fit starts again.

**Panels:**
- **SSB resource grid:** mean of the last 25 SSBs, 240 subcarriers × 4 symbols, dB over the noise.
- **PBCH constellation:** MMSE-equalised. After a decoded MIB, points are coloured by the symbol that was sent; the big dots are the mean per colour.
- **Latest cut:** power with the four OFDM symbols marked.
- **Channel estimate.**
- **Over time:**
  - CFO of the decoded SSBs, with the chip's own estimate and the CFO the measured clock rate implies;
  - SFN-anchored frame timing with a quadratic clock fit, plus the clock error now (ppm) and its change per minute;
  - SNR (o MIB decoded, x failed).
- **Side panel, in four tabs:**
  - **Cell:** stream counters (including board losses), the latest MIB fields with RSRP (dBFS, not calibrated) and the chip's PCI, the cell table;
  - **MIB:** the MIB of up to three cells side by side, every field in words (`capture/nr_mib.py`):
    - Raw fields: the number of MIBs and whether the content ever changed, SFN, half frame, SSB indices, subcarrier spacing, k_SSB, DM-RS position, cellBarred, intraFreqReselection.
    - Computed from `pdcch-ConfigSIB1` (TS 38.213 V17.14.0, Tables 13-1 and 13-11, 15 kHz): whether SIB1 is announced, the size and frequency band of CORESET#0, and the slots and symbol where the PDCCH for SIB1 is sent.
    - Click a row for what it means.
    - Below the table: cells with the same SSB frequency and MIB (most likely sectors of one site), and which cells announce SIB1. A change of a cell's MIB is logged.
  - **Channel:** see below;
  - **Log.**
  - A line below the tabs shows the latest message.
  - The panel takes the width its contents need at the desktop's font size, and the window grows to fit it (`--geometry WxH` overrides).

**Controls:**
- Click a row of the cell table to show or hide a PCI, double-click to show only it, "Show all" to undo; `--hide 165` starts with PCIs hidden.
- **Channel panel** (live only):
  - **Track:** retunes the board to the LO and SSB frequency typed in. SSB "auto" scans the raster at that LO first. An SSB more than 6.1 MHz from the LO (or within 2 MHz of it) moves the LO next to the SSB.
  - **Scan:** searches the whole SSB raster at a list of LOs, like `cell_scan`.
    - The LO list: `2131 2670`, a range `2175-2715/12`, or `2g` / `5g` / `2g 5g` (in the drop-down) for the C5's whole range.
    - "looks per SSB" (1–4, default 2) sets how often every SSB position of the 20 ms period must be covered at each LO.
    - Next to it the window shows the number of LOs and the estimated time, e.g. "152 LOs, about 14 min".
    - The line below the tabs shows the progress ("LO 41/152, 4 cells, about 12 min left"); Stop ends the scan.
    - The table lists band (with "30k" for 30 kHz SSBs), LO, SSB frequency, PCI, MIBs, SNR and CFO of every cell found.
  - **Double-click a found cell** to track it: LO, SSB, N_ID2 and CFO come from the scan, so the chip searches only that N_ID2 within ±10 kHz and locks on within seconds. Cells with 30 kHz SSBs cannot be tracked: the chip's detector and the live decoder handle 15 kHz only.
  - **Right-click a PCI in the cell table** → "Track PCI … on the chip". This switches the chip to that PCI's N_ID2 at the same frequency, e.g. to the other sector of a site, which the PC decodes from the same cuts.
  - **CFO centring:** once the SFN timing or a decoded cell of a scan has measured the board's crystal (ppm), scans and new channels centre their CFO search on it (scans: ±2 ppm instead of ±12 ppm). That matters at 5–6 GHz, where a few ppm are tens of kHz.
  - A switch stops the running stream (one board, one receiver), starts a new run (new session with `--record`) and clears the plots.
- **Tested on the board (24 Nov):**
  - scan of 2131 and 2670 MHz, then a double-click on PCI 317 (n7): 95 MIBs from 96 SSBs, 4.7 s after the click;
  - right-click from PCI 165 to its sector PCI 166 (chip on N_ID2 1): 49 MIBs from 62 SSBs at −5.5 dB.
- "Save PNG" writes the figure to `results/`.
- `--quit-after S --snapshot x.png` saves the figure and a window grab, then quits (used by the tests on a virtual display).

## Headless monitor

```bash
.venv_local/bin/python -m capture.ssb_monitor --port /dev/ttyACM0 --freq 2131 --jsonl results/monitor.jsonl \
    --csv results/monitor.csv --expect-pci 165 166 [--udp 127.0.0.1:5005] [--duration 3600]
.venv_local/bin/python -m capture.ssb_monitor --replay samples/ssbdet_pci165_150cuts --speed 0 --stdout
```

**Board handling and decoding:** the same as the live view, without a window.

**Output:** every decoded SSB as one JSON object, written to a file, stdout or a UDP feed, and as a CSV row. The fields: PCI, SFN, SSB index, SNR, RSRP, CFO, PSS and frame time, timing residual, MIB.

**Alerts** (also on stderr):
- `new_pci`: a PCI not in `--expect-pci`;
- `mib_change`: the MIB changed;
- `sfn_jump`: the SFN does not advance with the clock;
- `timing_jump`: the frame start leaves the running fit by more than `--timing-alert-us`;
- `cfo_outlier`: more than `--cfo-alert-hz` from the cell's median;
- `board`: a reconnect, with the reset reason from version 3.

**On the sample:** 177 MIBs, an event for PCI 165, an alert for PCI 166 (`--expect-pci 165`), no false alerts.

## SigMF export

```bash
.venv_local/bin/python -m capture.sigmf_export samples/ssbdet_pci165_150cuts results/ssb_sample
.venv_local/bin/python -m capture.sigmf_export data/<session> results/<name> --ssb results/<session>_ssb.csv
```

**What it writes:** `<name>.sigmf-data` (ci8 for CAP16, ci16_le for CAP20) and `<name>.sigmf-meta`.

**Metadata:**
- **Capture segments:** one per burst, with its centre frequency and the board's timestamp.
- **Annotations:** one per SSB, labelled with PCI, SSB index and SFN when a detection CSV is given.

**Caveat:** the bursts are not contiguous in time; use the capture segments.

## Band survey

```bash
.venv_local/bin/python -m capture.capture_bursts capture --port /dev/ttyACM0 --freq $(seq 2175 15 2715) \
    --per-freq 60 --count 2220 --rate 20 --bits 8 --gain 72 --label survey_2175_2715
.venv_local/bin/python -m capture.band_survey data/<survey> [data/<survey2>] --out results/band_survey.png \
    [--ssb results/<survey>_ssb_<tag>.csv]
```

`band_survey` averages the spectrum per LO, keeps the central ±8 MHz, stitches everything onto one axis with approximate band allocations, and prints the occupied stretches. NR cells hardly show in an averaged spectrum (an idle cell sends almost only its SSBs). So search the survey for SSBs with the MATLAB detector, centring the CFO window on the board's crystal error at the time (see [hardware.md](hardware.md)):

```matlab
addpath('matlab');
detect_session('data/<survey>', 'CFOCenter', -7.1e3, 'CFOMax', 10e3, 'Tag', 'scs15');                 % 15 kHz, L_max 4
detect_session('data/<survey>', 'SubcarrierSpacing', 30, 'Lmax', 8, 'CFOCenter', -7.1e3, 'Tag', 'scs30');
detect_session('data/<survey>', 'FreqMHz', [2655 2670], 'Tag', 'n7');                                 % only some LOs
```

`detect_session` writes `results/<session>[_<tag>]_ssb.{md,csv,mat}`:
- one CSV row per PSS peak: PCI, SSB index, CFO, SNR, MIB, SFN, PSS time and frame time;
- a summary by cell, and SSS statistics summed over bursts for cells too weak for one burst.

It loads the bursts in blocks of 200, so large surveys fit in memory. Use `CFOCenter` = −ppm × f.

## The NumPy receiver

```python
from capture import nr_ssb as nr
from capture.session import load_session
meta, recs, iq = load_session("samples/ssbdet_pci165_150cuts")
r = recs[0]
out = nr.receive(iq[0], r["fs"], r["ssb_pss_in_cut"], f_ssb=2125.45e6, f_lo=2131e6,
                 cfo=r["ssb_cfo_hz"], nid2=r["ssb_nid2"], t_first_us=r["t0_us"])
print(out["pci"], out["issb"], out["mib"], out["cfo"], out["snr_db"], out["t_frame_us"])
# plain bursts (no on-chip detection): find the PSS first
peaks = nr.pss_search(burst_iq, 20e6, offset_hz=2125.45e6 - 2131e6)   # [{"t_pss", "nid2", "stat", "cfo"}, ...]
```

`receive()` returns:
- the 240 × 4 grid, the channel and the MMSE-equalised PBCH symbols;
- the PCI, SSB index and half frame, the MIB (a dict, or `None`);
- the CFO (Hz), SNR per resource element, PSS time and frame start (µs).

Options:
- `scs=30e3, lmax=8, pattern="C"` for 30 kHz SSBs and 8 beams;
- `scale` converts payload units to 10-bit counts for the RSRP.

`nr_ssb.pss_search_raster(x, fs, offsets, cfos, scs=...)` searches many raster positions at once, and `nr_ssb.gscn_raster(fmin, fmax)` lists them.

## MATLAB tools

| Function | Purpose |
|---|---|
| `ssb_detect(x, fs, 'fLO', f, ...)` | one burst: GSCN search, PSS over CFO hypotheses, SSS, CFO refinement with the TS 38.211 symbol phase removed (`SymbolPhase`), DM-RS, PBCH, BCH; options `fSSB`, `SubcarrierSpacing`, `Lmax`, `CFOCenter`, `CFOMax`, `KeepTrace` |
| `detect_session(folder, ...)` | the above over a session, summary by cell |
| `sib1_offline(folder, 'FreqMHz', lo, 'SSBMHz', f, 'PCI', p)` | SIB1 of one cell from a session of full bursts: the bursts with its MIB fit the cell's frame clock on the board's clock; the slots of the SIB1 control channel (from `pdcch-ConfigSIB1`) that lie whole in a burst are demodulated over CORESET#0; blind PDCCH decoding with the SI-RNTI, DCI format 1_0, then PDSCH and DL-SCH (5G Toolbox). Writes `results/sib1_<session>_<PCI>.mat/.json` (the decoded SIB1 as hex) |
| `sim_ssb_detection` | Monte Carlo of detection and MIB decoding against SNR (AWGN, C5 receiver model) |
| `ssb_test_waveform`, `c5_rx_model` | SSB-only test signal with ground truth (`CarrierFrequency` adds the RF symbol phase a real gNB applies); simulated C5 capture |
| `make_n310_ssb_waveform` | SSB and CW files for a cabled test with a USRP (sensitivity in dBm). **Cable and attenuators only.** |
| `export_pbch_tables` | the polar tables for `capture/nr_pbch_tables.py` and the test vectors in `tests/fixtures/nr_pbch_vectors.json` |

Never pipe `matlab -batch` output: recent MathWorks service hosts keep the pipe open. Redirect to a file instead: `matlab -batch "..." > log 2>&1 < /dev/null`.
